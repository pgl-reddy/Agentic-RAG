  Shape 4 [TextBox 5] (type: TEXT_BOX (17))
    - Large Language Models can provide fluent answers, but responses may be unreliable, outdated, or unsupported by authoritative evidence. Hence, Grounding is used in AI. Grounding is a practice of connecting an AI model’s output to verifiable, real-world data or trusted external sources. Grounding matters to
    - Reduce Hallucinations – Stops AI from faking data
    - Adds traceability – clear citations to original sources
    - Keeps data current – to answer using up-to-date information
    - Common grounding techniques involve Retrieval-Augmented Generation (RAG). Existing work Agentic RAG can improve answer quality by evaluating a generated response and repeating retrieval when the response is inadequate.
    - The proposed system moves control before generation: query analysis, reformulation, retrieval routing, evidence sufficiency assessment.
    - Retrieval is dynamically selected from sparse, dense, and hybrid modes according to the legal query.
    - If evidence is insufficient, the query is reformulated and retrieval is repeated; otherwise, a grounded answer with citations is generated.
    - The project focuses on integration of known techniques into a pre-generation retrieval-control loop for legal question answering.

    - Legal answers often depend on legal sections, case names, citations, legal terminology, and recent amendments.
    - General LLMs may answer from learned parameters without verifying whether current legal evidence supports the response.
    - Generated Information can be unreliable, outdated, or insufficiently grounded.
    - RAG improves grounding by retrieving source documents before generation. But a RAG system can still retrieve weak, irrelevant or incomplete evidence.
    - Thus, an Agentic RAG approach, adds iterative decision-making and quality checking.

  Shape 3 [TextBox 5] (type: TEXT_BOX (17))
    - Analyze the legal query for legal terms, entities, case references, citations, and ambiguity.
    - Reformulate weak or ambiguous queries before retrieval.
    - Route each query to BM25 sparse retrieval, dense semantic retrieval, or hybrid retrieval.
    - Re-rank retrieved passages using a cross-encoder relevance model.
    - Assess evidence sufficiency before allowing the LLM to generate an answer.
    - Retry with a reformulated query when evidence is insufficient.
    - Return an explicit insufficient-evidence response when adequate support cannot be obtained within the retry limit.

      | Query reformulation | LLM-based reformulation + threshold rules | Improve weak / ambiguous queries |
      | Sparse retrieval | BM25 | Exact lexical matching for sections, names, citations |

      | Evidence check | Score threshold + LLM evidence judgment | Decide whether evidence is sufficient |
      | Generation | Grounded LLM answer with citations | Generate only from assessed evidence |
